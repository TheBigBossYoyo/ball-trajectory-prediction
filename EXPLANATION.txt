Trajectory Prediction System: Physics vs. LSTM
==============================================

This document explains the two core components of the Trajectory Prediction System: the deterministic Physics Engine and the probabilistic LSTM Neural Network.

1. Physics Engine (Deterministic)
---------------------------------
The "Physics" trajectory (Blue line) is calculated using classical Newtonian mechanics. It represents an "idealized" world.

*   **Logic**: It solves the equations of motion step-by-step (Velocity Verlet integration).
*   **Forces**:
    *   **Gravity**: Constant downward acceleration ($g = 9.81 m/s^2$).
    *   **Drag**: Air resistance proportional to velocity squared ($F_d \propto v^2$). This depends on the ball's mass, radius, and shape.
    *   **Restitution**: When the ball hits the ground, it reverses direction with a loss of energy ($v_{new} = -v_{old} \times C_R$).
*   **Characteristics**:
    *   Smooth, predictable curves.
    *   Consistent energy loss on every bounce.
    *   Does not "learn" from data; it behaves exactly as programmed.

2. LSTM Neural Network (Probabilistic/AI)
-----------------------------------------
The "LSTM AI" trajectory (Red line) is generated by a Recurrent Neural Network (RNN). It represents a "learned" understanding of how objects fall.

*   **Logic**: The Long Short-Term Memory (LSTM) network takes a sequence of past positions (e.g., the last 0.1 seconds of the ball's fall) and predicts the *next* position. This process is repeated (autoregression) to generate the full path.
*   **Training**: The model was trained on a mix of:
    *   **Synthetic Data**: Physics simulations with randomized parameters (mass, bounciness).
    *   **Real Sensor Data**: Actual recordings of falling balls (from `data.csv`).
*   **Characteristics**:
    *   Can capture subtle real-world nuances that a simple physics formula might miss (if trained heavily on real data).
    *   May exhibit "imperfections" or wobbles, which mimic sensor noise or uncertainty.
    *   **Generalization**: It learns the *concept* of gravity and bouncing. It is not just memorizing the physics formula; it is predicting the pattern.

3. Key Differences
------------------
| Feature | Physics Engine | LSTM AI |
| :--- | :--- | :--- |
| **Basis** | Mathematical Formulas | Statistical Patterns |
| **Accuracy** | Exact (in ideal conditions) | Approximate (based on training) |
| **Input** | Initial Conditions (height, mass) | Sequence History (past movement) |
| **Robustness** | 100% Stable | Can diverge or "hallucinate" if input is unusual |
| **Purpose** | Ground Truth / Reference | Predicting future states from sensor data |

4. How to Use This Comparison
-----------------------------
*   **Validation**: Use the Physics line as a baseline to see if the LSTM understands the scenario. If the Red line follows the Blue line closely, the AI has successfully learned the physics of that specific ball.
*   **Sensor Data**: The Green line is recorded data. Use the "Rubber Ball" setting to see how well both the Physics (ideal) and LSTM (learned) match reality.
